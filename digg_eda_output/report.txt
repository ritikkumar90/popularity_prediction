======== 11. DESIGN NOTES (rule-based, read together with the numbers above) ========
1. Target is heavy-tailed (skew 6.5; 1.0 after log1p): regress on log1p(votes) or use quantile classes; plain MSE on raw counts will be dominated by a few viral stories.
2. Early-vote Spearman reaches 0.8 at window = 24.0h.
3. Pick the observation window from the early-signal table: the smallest window with a good 'vs remaining votes' correlation. Build ALL features and ALL graph edges from that window only.
4. 48% of votes (whole cascade) follow an earlier friend vote; Spearman(exposure, popularity)=0.46. Caution: this is measured over the FULL cascade and is partly mechanical (big cascades are exposed by chance). It shows the 'follows' edges carry cascade structure, but as a model feature recompute exposure ONLY inside the early window, otherwise it leaks the future.
5. Degrees are extremely skewed: use neighbour sampling (e.g. PyG NeighborLoader) with capped fan-outs, and log-transform degree features.
6. Graph is large for full-batch training: mini-batch around the target stories with sampling.
7. No raw node attributes exist: for R-GCN/HGT initialise User nodes with log-degree/activity features (or learned embeddings) and Story nodes with early-window statistics (early votes, early voter followers).
8. XGBoost baseline: start from story_table.csv; it is the reference every graph model must beat. Check the feature-signal table to see which engineered features carry information.
